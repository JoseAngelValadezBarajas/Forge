# QA-01 + DOC-01: Design

## Goal

Strengthen product acceptance coverage for the implemented Forge Alpha and publish a reproducible Spanish user guide based on real, deterministic application screens.

## Boundaries

The work stays on the shared browser application and its isolated FastAPI/SQLite E2E runner. It does not alter Desktop IPC, sidecar, Tauri packaging, API contracts, product data models, FND-07, WEB-01, iOS, or release publishing. Existing visual baseline snapshots remain authoritative and are not updated.

## Quality approach

The coverage matrix records the current E2E suites and the selected gaps. New browser tests use existing real backend fixtures and semantic locators. They add only cross-feature and negative coverage that is absent: planning search/navigation restoration, archive restrictions, unauthorized repository rejection/no write, stale/missing Workbench information, and delivery gates blocked by missing required evidence. The isolated runner continues to own temporary SQLite files and temporary Git repositories, with zero retries and no reuse of external servers.

The existing Windows UI Automation installed-product smoke remains the Desktop acceptance boundary. This milestone may document its scope but will not add CDP, WebView debugging, browser automation, or an installer change.

## Documentation approach

`docs/user-guide/README.es.md` is the canonical Mexican-Spanish manual. A deterministic Playwright fixture creates scrubbed screenshots in `docs/user-guide/assets/`; it uses the real browser application and temporary fixtures. A Node documentation builder, using the already-pinned Playwright runtime, validates the Markdown structure and links, writes portable HTML, and prints a PDF. HTML and Markdown are committed; the PDF is generated into an ignored output directory and uploaded by CI. The exported PDF has a cover, linked table of contents, headers/footers, page numbers, print margins, deliberate page breaks, real screenshots, and verified internal/external links.

## Acceptance evidence

The build command captures no personal data, validates asset references and Markdown links, emits HTML/PDF, and is checked by automated tests. The PDF is rendered back to page images and inspected for page count, image dimensions, overflow, and footer/page-number presence. Certification runs the established backend, frontend, visual, E2E isolation, secret, documentation, Windows installed-product, GitHub Actions, and CodeQL checks. Any discovered functional defect gets a focused regression before a minimal fix.
